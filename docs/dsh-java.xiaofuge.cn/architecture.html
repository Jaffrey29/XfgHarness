App

启动装配层：Spring Boot 配置、Bean 组装、Profile 切换（standalone / 标准部署）。

Trigger

入口适配层：19 个 REST Controller、SSE 通道、API Key 鉴权，把外部协议翻译成内部调用。

API / Case

Facade 与 DTO 定义系统对外契约；Case 层用策略树编排用例流程，组合领域能力。

Domain

核心领域：Agent、Session、Task、Tool、Plugin、Runtime 六大聚合，27 个限界上下文，纯领域逻辑无框架依赖。

Infrastructure

端口实现：MySQL/H2 仓库、LLM 客户端、Shell 执行环境、MCP 通道，可整体替换。

Types (SPI)

轻量契约包：插件只依赖它，与宿主内部实现完全解耦。

Dependency Rules

单向依赖：复杂度的护城河

模块依赖方向被严格约束，任何反向依赖都无法通过编译。这让 27 个限界上下文可以独立演进而不互相污染。

App装配与启动
Trigger协议入口
API / Case契约与编排
Domain核心领域
Infrastructure适配实现（反向依赖 Domain 端口）

约束规则

  • 依赖方向：App → Trigger → API/Case → Domain ← Infrastructure
  • Domain 不 import 任何框架与外部 SDK
  • 插件仅依赖 Types SPI 契约包

带来的收益

  • LLM 客户端、数据库、执行环境均可替换
  • 领域逻辑可脱离容器做纯单元测试
  • 新能力以插件形式扩展，不改核心代码

对话主线：从 HTTP 到 Agent 会话聚合

HTTP/SSE 请求进入 Trigger 层，经 Facade 到达用例编排，再由 Agent 会话聚合维护消息历史、运行状态和工具调用事件。

Trigger鉴权 · 参数校验
Facade / Case用例编排 · 策略树
Session 聚合消息 · 状态 · 事件
ReAct 引擎推理与工具循环
Line 02 · Task

任务主线：评估、队列、审批、执行

任务提交后经过权限评估进入队列，高风险节点转人工审批，执行结果回写；目标、计划、待办和工作流围绕任务上下文协作。

任务提交目标与上下文组装
权限评估风险矩阵分级
队列调度排队与并发控制
审批节点高危操作人工确认
执行回写结果与状态落库
Line 03 · Event Sourcing

事件溯源主线：系统的记忆

Session Event Log 是会话的唯一事实来源。它记录用户输入、模型输出、工具调用与审批状态，支撑回放、审计与轨迹分析三大能力。

↺回放

从事件流重建任意时刻的会话状态，复盘 Agent 的每一步决策。

✓审计

谁在何时批准了哪条高危命令、工具拿到了什么参数，全部可查。

⌁轨迹分析

控制台轨迹视图基于事件流渲染，定位低效循环与失败根因。

Line 04 · Plugin Loading

插件加载主线：从 JAR 到可用工具

插件不是装上就能用——它要经过描述解析、实例创建、工具注册三道关卡，才会暴露给 Agent。

plugin.yamlMETA-INF 描述文件解析
SPI Loader隔离 ClassLoader 创建实例
生命周期安装 → 激活 → 停用 → 卸载
ToolRegistry工具注册进统一注册表
暴露给 Agent进入模型工具清单

为什么工具必须过 ToolRegistry

统一注册表是治理的闸口：只有注册过的工具才会进入模型的可用工具清单，也才会被权限矩阵与 Hook 链覆盖。未注册代码即使在进程内，Agent 也触达不到。
